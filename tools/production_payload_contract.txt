# STEMwerk 2.3.1.0 authoritative production payload contract.
#
# The set of repo-relative files required (or explicitly optional) for a
# correctly installed production copy of STEMwerk, independent of any
# single distribution route (ReaPack/index.xml, deb, rpm, Arch, macOS,
# Windows).
#
# Format: one entry per line, <requirement><TAB><platform><TAB><repo-relative-path>.
# requirement is one of: required, optional.
# platform is one of: common, linux, macos, windows.
# "common" entries apply on every platform; platform-tagged entries apply
# only to that platform's native install AND to ReaPack (which serves all
# platforms from one shared catalog, so it needs the union of everything).
#
# required: absence makes supported production functionality/Setup/Repair
#   incorrect on an applicable platform. Hard release-gate failure.
# optional: may be packaged and is a real, advertised, supported product
#   surface, but its absence must not fail installation/runtime
#   completeness (e.g. the single-size toolbar icons: not read by the
#   automated toolbar-install action, but explicitly offered in that
#   action's own UI text for manual/custom use). Reported, never a
#   release-gate failure on its own.
# Anything not listed here at all is a packaged extra (not tracked) --
# used for things like README/LICENSE or dev/benchmark scripts that ship
# in some native routes today but are neither required nor an advertised
# optional feature.
#
# Path syntax is fail-closed: no absolute paths, no backslashes, no empty
# segments, no "."/".." traversal, must already be in normalized form.
# The same path may appear under two different specific platforms (e.g.
# both macos and linux) to express a shared-but-not-universal requirement,
# but not under both "common" and any specific platform for the same path
# (redundant/contradictory), and not with two different requirement
# classes for the same path (ambiguous). See
# tools/release_gate.py:parse_production_payload_contract() for the exact
# validation rules.
#
# This is release-engineering source-of-truth data, not generated from
# and not copied from any single existing distribution manifest. It was
# built from independent evidence: released entrypoints, Setup/Repair
# code paths, actual runtime dofile/import/subprocess call sites, and
# existing native build tooling -- see
# tools/release_gate.py:check_production_payload_contract() for how
# it is consumed, and the 2.3.1.0 release-prep evidence archive for
# the full audit trail (including a corrective pass after independent
# review found two under-included pyproject.toml build-metadata files,
# one platform misclassification, two unused/stale wheels, 40
# over-included files that are actually optional, and two dead _internal
# Lua files that had been blanket-assumed required).
#
# Source-code reachability scanning (tools/release_gate.py's static
# dofile/loadfile scan and its small dynamic-dispatch declaration)
# remains useful as defense-in-depth and a drift signal, but this file
# is the normative list every distribution route is checked against.
#
# Deliberately excluded (not production-required, not optional, no
# contract entry at all): tests, benchmarks, dev-only debug-toggle/
# manual-fallback scripts, CI/i18n-validation tooling, release/build
# scripts themselves, docs not read at runtime, and packaging metadata
# not imported by any runtime code (unless, like the two pyproject.toml
# files above, it is itself required as build/install-time input by a
# bootstrap script).
#
# Update this file, with evidence, whenever a new file becomes part of
# a supported release flow, or a classification needs correcting.
